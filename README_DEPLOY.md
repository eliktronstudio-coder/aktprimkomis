# Инструкция по развёртыванию — Приёмочная комиссия

Подробная пошаговая инструкция для новичка. Все сервисы используются на **бесплатных тарифах**.

---

## Что понадобится

- Аккаунт GitHub
- Браузер Chrome или Firefox
- ~30 минут свободного времени

---

## Шаг 1. Получите код проекта

1. Откройте GitHub и войдите в свой аккаунт
2. Откройте репозиторий проекта и нажмите **Fork** (вверху справа)
3. Дождитесь создания копии репозитория в вашем аккаунте

Либо клонируйте локально:
```bash
git clone https://github.com/YOUR_USERNAME/priemochnaya-komissiya.git
cd priemochnaya-komissiya
```

---

## Шаг 2. Создайте проект Supabase

1. Перейдите на [supabase.com](https://supabase.com) и нажмите **Start your project**
2. Войдите через GitHub
3. Нажмите **New project**, заполните:
   - **Name**: `priemka` (или любое)
   - **Database Password**: придумайте и сохраните пароль
   - **Region**: выберите ближайший к вам (Europe West или другой)
4. Нажмите **Create new project** и подождите ~2 минуты

### Запустите миграцию базы данных

1. В левом меню Supabase выберите **SQL Editor**
2. Нажмите **New query**
3. Выполните **по очереди, строго в этом порядке**, четыре файла из папки `supabase/migrations`:
   `001_initial.sql` → `002_security_fixes.sql` → `003_act_snapshot.sql` → `004_storage.sql`.
   Для каждого: откройте файл, скопируйте всё содержимое, вставьте в редактор, нажмите **Run** (Ctrl+Enter)
4. После каждого файла внизу должно появиться `Success. No rows returned`

> Проще: откройте один файл `supabase/setup_all.sql` (в нём все четыре миграции подряд), вставьте целиком и нажмите **Run**. Запускать нужно один раз на пустой базе.

### Настройте вход по email

1. **Authentication** → **Providers** → **Email** должен быть включён
2. Для простого старта можно отключить **Confirm email** (иначе новым пользователям придёт письмо с подтверждением;
   на бесплатном тарифе Supabase письма ограничены несколькими штуками в час)
3. **Authentication** → **URL Configuration** → в **Site URL** впишите адрес вашего сайта на Cloudflare Pages (после шага 4)

### Получите ключи Supabase

1. В левом меню выберите **Project Settings** → **API**
2. Скопируйте и сохраните:
   - **Project URL** → это `VITE_SUPABASE_URL` и `SUPABASE_URL`
   - **anon public** ключ → это `VITE_SUPABASE_ANON_KEY`
   - **service_role** ключ (нажмите Reveal) → это `SUPABASE_SERVICE_ROLE_KEY`

> ⚠️ service_role ключ — секретный! Никому не показывайте и не коммитьте в git.

## Шаг 3. Хранилище фото (Supabase Storage, карта не нужна)

Фото хранятся в бакете `photos` самого Supabase: бесплатно 1 ГБ (около 80 актов по 30 фото). Бакет создаёт миграция `004_storage.sql`, вручную ничего настраивать не нужно.
Если места станет мало, в Supabase можно перейти на платный тариф или перенести фото в другое хранилище.

> Бакет публичный: адреса фото содержат длинные случайные идентификаторы, но любой, кто получит ссылку, сможет открыть снимок. Не публикуйте ссылки на фото в открытых местах.

## Шаг 4. Настройте Cloudflare Pages

1. В Cloudflare Dashboard → **Pages** → **Create a project**
2. Выберите **Connect to Git** → подключите GitHub аккаунт
3. Выберите ваш репозиторий с проектом
4. Настройки сборки:
   - **Framework preset**: `Vite`
   - **Build command**: `npm run build`
   - **Build output directory**: `dist`
5. Прокрутите вниз до **Environment variables** и добавьте (для **Production**; если используете Preview — и для него тоже):

| Переменная | Значение |
|-----------|---------|
| `VITE_SUPABASE_URL` | URL вашего Supabase проекта |
| `VITE_SUPABASE_ANON_KEY` | anon ключ Supabase |
| `SUPABASE_URL` | URL вашего Supabase проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role ключ Supabase |
| `NODE_VERSION` | `20` |

6. Нажмите **Save and Deploy**. Переменные `VITE_*` вшиваются в сайт при сборке: после их изменения нужен повторный деплой
7. Дождитесь первого деплоя (~2-3 минуты)
8. Сайт будет доступен по адресу вида `https://priemka-xxx.pages.dev`

---

## Шаг 5. Импортируйте шаблон чек-листа

1. Скопируйте файл `template.xlsx` в корень проекта (рядом с `package.json`)
2. Создайте файл `.env.local` в корне проекта:

```
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

3. Установите зависимости и запустите скрипт:

```bash
npm install
npm run import-template -- --dry-run   # проверка без записи в базу
npm run import-template                # импорт
```

4. Проверка разбора шаблона (`--dry-run`) должна показать:
```
Found 84 sections, 238 items
  Zones: 27, subsections: 57, КЗ: 52
```
После настоящего импорта в конце будет `✓ Template imported successfully!`

## Шаг 6. Настройте GitHub Actions для keepalive

Чтобы Supabase не «засыпал» (на бесплатном тарифе после 7 дней без активности):

1. В вашем репозитории GitHub → **Settings** → **Secrets and variables** → **Actions**
2. Нажмите **New repository secret** и добавьте:
   - `SUPABASE_URL` — URL проекта Supabase
   - `SUPABASE_ANON_KEY` — anon ключ Supabase
3. Workflow будет автоматически запускаться каждые 3 дня

## Шаг 7. Создайте первого пользователя-администратора

1. Откройте ваш сайт на Cloudflare Pages
2. Зарегистрируйтесь через форму входа
3. В Supabase → **SQL Editor** выполните (подставьте свой email):
```sql
update profiles set role = 'admin' where email = 'you@example.com';
```
(напрямую менять роль через интерфейс сайта может только уже существующий администратор)
4. Обновите страницу сайта — появится раздел «Администрирование» с пользователями, шаблоном и счётчиком занятого места
5. Остальным сотрудникам: пусть сами зарегистрируются, а вы назначите им роль в разделе «Администрирование» → «Пользователи»

### Как подрядчик получает доступ к акту

1. Подрядчик регистрируется на сайте, администратор назначает ему роль «Подрядчик»
2. Инженер открывает акт → вкладка **Доступ** → выбирает подрядчика и «Ответственного» (например, «Ген.подрядчик по СМР») → **Добавить**
3. Подрядчик увидит только этот акт и только замечания своего ответственного, сможет загружать фото устранения и ставить «Замечание устранено»

## Структура ролей

| Роль | Описание |
|------|---------|
| `admin` | Полный доступ: шаблон, пользователи, все акты |
| `engineer` | Создаёт и редактирует акты, отмечает замечания |
| `contractor` | Видит только свои акты, загружает фото устранения |

## Часто задаваемые вопросы

**Q: Сайт открывается, но пишет ошибку подключения к базе**
A: Проверьте, что переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` правильно заданы в Cloudflare Pages → Settings → Environment variables

**Q: Фото не загружаются**
A: Проверьте, что выполнена миграция `004_storage.sql` (в Supabase → Storage должен быть бакет `photos`) и что в Cloudflare Pages заданы `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`

**Q: Как обновить шаблон после изменений в Excel?**
A: Замените `template.xlsx` в корне проекта и снова запустите `npx tsx scripts/import-template.ts`

**Q: Как установить сайт на телефон как приложение?**
A: Android (Chrome): меню ⋮ → «Установить приложение». iPhone (Safari): «Поделиться» → «На экран Домой».

**Q: Что будет, если на объекте пропадёт интернет?**
A: Изменения и фото сохранятся на телефоне, в шапке появится значок «● N неотпр.». Когда связь вернётся, всё отправится автоматически. Не очищайте данные сайта в браузере, пока значок не исчез.

**Q: Изменил шаблон — изменятся ли уже созданные акты?**
A: Нет. Акт — самостоятельная копия шаблона на момент создания.

**Q: Приложение «засыпает» и не открывается через неделю без использования**
A: Проверьте, что в GitHub → Actions включён workflow «Supabase Keepalive» и заданы секреты `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Запустить вручную можно кнопкой **Run workflow**.
